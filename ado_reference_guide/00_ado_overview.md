# 🚀 Azure DevOps Overview

Azure DevOps (ADO) is an all-in-one suite of tools that helps us manage the entire software development lifecycle. For most of your daily work, you will spend 90% of your time in two specific menu sections: **Boards** and **Repos**.

## 📋 The Core Modules

### 1. Boards
Located in the left-hand navigation menu under **Boards**, this is the planning hub. It replaces tools like Trello or Jira. This is where we track *what* needs to be built and *who* is doing it.

Key areas you will use:
* **Backlogs**: The master list of everything we intend to do.
* **Sprints**: The specific bucket of work committed to for the current iteration.
* **Boards**: A visual representation of work moving from "To Do" to "Done."

### 2. Repos
Located under **Repos** in the left menu, this is our version control system (Git). This is where the actual code lives.

Key areas you will use:
* **Files**: The source code browser.
* **Commits**: The history of every change made to the codebase.
* **Pull Requests (PRs)**: The gateway for getting your code reviewed and merged into the main branch.

## 💡 Narrative Example: A Day in ADO

Imagine you start your day. You first navigate to **Boards > Sprints** to see your assigned tasks for the current sprint. You find a task called "Implement Login Validation." 

Once you understand the requirements, you move over to **Repos > Files** to create a new branch. After writing your code, you go to **Repos > Pull Requests** to submit your changes for review, making sure to link the "Implement Login Validation" work item so your teammates know exactly which task this code satisfies.
