# 🚀 Extreme Programming (XP) Reference Guide

**Goal:** To provide junior developers with a broad, shallow dive into Extreme Programming (XP) practices, demonstrating how these technical "power-ups" complement the Scrum framework to improve code quality and team agility.

## 🧐 Why XP for Scrum Teams?
While Scrum provides the organizational structure (Sprints, Roles, Ceremonies), XP provides the technical discipline. By adopting XP practices, we move from simply "managing" our work to "engineering" our software with excellence.

## 💡 How to Use This Guide
This is not a rulebook, but a **best-practices overview**. Junior developers are encouraged to:
1. Read through the modules to understand the *intent* behind the practices.
2. Identify one practice (e.g., TDD or Pairing) to try during the next Sprint.
3. Discuss with your mentor or team how these practices can be integrated into our specific workflow.
