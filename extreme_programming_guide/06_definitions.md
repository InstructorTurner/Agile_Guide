# 📖 06: Definitions - The XP Glossary

**Goal:** A quick-reference guide to the terminology used throughout the Extreme Programming framework.

## 🔤 Key Terms

- **TDD (Test-Driven Development):** A cycle of writing a failing test, making it pass, and then cleaning up the code.
- **Pair Programming:** Two developers, one keyboard, one goal. One drives (types), one navigates (reviews).
- **Refactoring:** Improving the "how" of the code without changing the "what" of the feature.
- **YAGNI (You Ain't Gonna Need It):** The practice of avoiding adding functionality until it is explicitly required.
- **CI (Continuous Integration):** Merging code to the main branch frequently (multiple times a day) to avoid "merge hell."
- **Collective Ownership:** The belief that any team member is responsible for and allowed to improve any part of the codebase.
- **The Planning Game:** The negotiation between the business (PO) and the technical team to determine the scope of a release.
- **Sustainable Pace:** A work speed that can be maintained indefinitely without leading to burnout or quality drops.
- **Whole Team:** A cross-functional group including the PO and developers working in tight lockstep.
- **Vertical Slice:** A minimal feature that works end-to-end (UI $\rightarrow$ Logic $\rightarrow$ DB).
